# Contributing to Relay

Thanks for helping. Relay stays deliberately small: a Swift menu bar app, a plain HTML/JS phone page, no dependencies and no servers. Changes that keep it that way are the easiest to accept.

## Proposing a change

- **Bugs and ideas:** open an issue describing what you expected and what happened (Mac model, macOS and iOS versions help).
- **Code:** open a pull request against `main`. Small, focused pull requests are reviewed fastest. For bigger changes, open an issue first so we can agree on the approach.
- **Security problems:** please don't open an issue. See [SECURITY.md](SECURITY.md).

## Development setup

You need a Mac on Apple silicon with macOS 14 or later, the Xcode command-line tools (`xcode-select --install`), and an iPhone on the same Wi-Fi. Node is only needed for one test.

```bash
git clone <your fork's URL> && cd Relay
git config core.hooksPath .githooks   # pre-commit secret checks and commit-message checks
./scripts/install.sh                   # build, install to ~/Applications, start
./scripts/pair.sh                      # QR code for your iPhone
```

Re-run `./scripts/install.sh` after every change; it rebuilds and restarts Relay. The phone page lives in `web/` and is bundled into the app.

- **Signing:** `scripts/build.sh` signs with your free "Apple Development" certificate if you have one (Xcode › Settings › Accounts). That keeps macOS permissions across rebuilds. Without one it signs ad hoc, and you may need to re-enable Relay under Accessibility after rebuilding.
- **Environment variables (optional):**
  - `RELAY_SIGN_IDENTITY` picks a signing identity.
  - `RELAY_BUILD_DIR` sets where the app is built.
  - `RELAY_WEB_ROOT` serves `web/` from a folder for quick page edits.

  None of them hold secrets, so there is no `.env` file.

## Tests

```bash
./tools/test.sh              # everything, against the installed Relay
node tools/cryptotest.mjs    # just the phone-side crypto, no Mac app needed
./scripts/check-repo.sh      # secret and personal-data checks (also run by the pre-commit hook and CI)
```

`tools/test.sh` moves the cursor, types into its own test window, and briefly changes the volume, restoring it afterwards, so don't use the Mac while it runs. Pass `--display` to also test turning the display off.

## Guidelines

- **Security review:** for anything that touches pairing, encryption, the network, permissions, or what is captured or logged, explain the security impact in the pull request and add a check to `tools/securitytest.swift` where possible.
- **Battery:** nothing may poll or run timers while idle; measure CPU when you add background work.
- **Data:** use made-up data in tests, examples and screenshots. Never commit keys, logs or your pairing code; the pre-commit hook blocks the obvious cases.
- **README:** update it when you change what users see or do.
- **Commit messages:** a short summary line and an optional body explaining why. No AI co-author or "generated by" lines.
